Critério de aceite literal (`docs/EMPACOTAMENTO.md` § Marcos):
"Marco 1 (sem assinatura): `.app` que sobe o backend embarcado, abre a janela no
webapp e encerra o backend ao fechar. Aceite: abrir num catálogo novo, escanear
fixtures, ver a grade; ao fechar, nenhum processo Python órfão
(`ps` / `~/.claude/scripts/portas.py`)."

Caminhos e nomes:
- binário nativo: `src-tauri/target/release/bundle/macos/Foto Organizer.app/Contents/MacOS/foto-organizer`
- comando do backend (spawnado por `main.rs`): `python3 -m fotoorganizer web --porta 0 --encerrar-com-pai`
- catálogo padrão: `~/Library/Application Support/FotoOrganizer/catalog.db`
- override de catálogo: env `FOTOORG_DATA_DIR` (`cli.py:122`), que também isola o
  cache derivado (`cli.py:126-132`). `main.rs` não passa `--data-dir` e usa
  `Command::new(py)` sem `.env_clear()`, então o ambiente do processo que abrir o
  binário é herdado pelo Python embarcado.

API local (guard de origem aceita `127.0.0.1`, `localhost`, `::1`):
- `POST /api/scan` com corpo `{"caminho": "<pasta>"}` → 422 se a pasta não existe,
  409 se já há trabalho em andamento
- `GET /api/job` → estado do trabalho corrente
- `GET /api/midia` → itens da grade
- `GET /api/pastas` → árvore de pastas

Desenho anti-órfão de duas camadas (já implementado, verificar — não substituir):
- Rust: `RunEvent::ExitRequested` → `libc::kill(child, SIGTERM)` → `child.wait()`
  (`src-tauri/src/main.rs`, bloco `.run(...)`)
- Python: `--encerrar-com-pai` liga `_vigia_pai()`, thread que confere `os.getppid()`
  a cada 2s e manda SIGTERM em si mesma se o pai morreu (`fotoorganizer/cli.py:664-679`)

    Descobrir o processo do backend com `pgrep -f "fotoorganizer web --porta 0"` e a porta
    efêmera com `lsof -nP -iTCP -sTCP:LISTEN -a -p <pid>`. Guardar pid do shell nativo, pid

    `GET /api/job` deve responder 200; `POST /api/scan` com `{"caminho": "<pasta de fixtures>"}`
    deve iniciar a varredura; consultar `GET /api/job` até o status sair de "em andamento";
    `GET /api/midia` deve devolver a mesma quantidade de itens que os JPEGs criados;
    `GET /api/pastas` deve devolver a árvore com as subpastas. Confirmar que o catálogo
    criado está no diretório descartável e que `~/Library/Application Support/FotoOrganizer/catalog.db`
    não teve o mtime alterado.

    Encerrar como um usuário encerraria: `osascript -e 'quit app "Foto Organizer"'`. Esperar
    alguns segundos e conferir os dois lados da rede anti-órfão:
    `pgrep -f "fotoorganizer web"` não deve achar nada, e a porta anterior não deve mais
    estar em LISTEN (`lsof -nP -iTCP:<porta> -sTCP:LISTEN`). Repetir o encerramento pelo
    caminho que pula o handler do Rust (`kill -9` no pid do shell nativo, numa segunda
    execução) para exercer especificamente o `_vigia_pai`: em até ~4s o Python deve sumir
    sozinho.

    Se qualquer etapa do caminho crítico falhar — o app não abre, o backend não anuncia
    `FOTOORG_READY`, a janela não carrega, a varredura não roda a partir do runtime
    embarcado, ou sobra processo órfão — corrigir aqui (D-03), dentro do desenho de duas
    camadas existente: SIGTERM no `ExitRequested` do lado Rust e `_vigia_pai` do lado Python.
    Não introduzir mecanismo novo de heartbeat, não trocar SIGTERM por SIGKILL (o SIGTERM é
    o que permite o uvicorn drenar e fazer checkpoint do WAL), e não mudar a arquitetura de
    porta efêmera + URL externa. Documentar cada defeito e cada correção no SUMMARY.

| T-05-21 | Spoofing | Requisição de origem externa contra a porta efêmera | accept | Guard `_HOSTS_LOCAIS` (`server/app.py:93,425-434`) já bloqueia Host/Origin não local e não é alterado por este plano; o uvicorn escuta apenas em 127.0.0.1 |
| T-05-22 | Tampering | Varredura de teste apontando para o acervo real | mitigate | Task 1 usa `FOTOORG_DATA_DIR` descartável e fixtures sintéticas; critério de aceite compara o mtime de `~/Library/Application Support/FotoOrganizer/catalog.db` antes e depois |
