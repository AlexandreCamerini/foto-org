## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| usuário → `POST /api/scan` (já existente) | O caminho digitado pelo usuário passa a poder ser submetido de quatro pontos da UI em vez de um. O endpoint, a validação e a autorização são exatamente os mesmos — nenhum código de servidor é tocado neste plano. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06-01 | Tampering / path traversal via caminho digitado | `POST /api/scan` | transfer | A validação de caminho é responsabilidade do servidor (`fotoorganizer/security`, invariante 5 do `CLAUDE.md`: argumentos em lista, sem `shell=True`, caminho validado, sem atravessar symlink). Este plano não altera o payload, o endpoint nem a validação — só multiplica os botões que chegam ao mesmo formulário já existente. Nenhuma validação nova no cliente: validar caminho no front daria falsa sensação de barreira e divergiria da regra do servidor |
| T-04-06-02 | Denial of Service (usuário dispara scan concorrente a partir de uma tela que não conhece o estado do job) | `App.tsx` / três estados vazios | accept | Os três botões novos não recebem `job` e portanto não desabilitam durante um job. O servidor já rejeita disparo concorrente, e a Task 1 garante que a mensagem de rejeição aparece no próprio modal. Custo aceito em troca de não prop-drillar `job` para três telas que não têm outro uso para ele |
| T-04-06-03 | Information Disclosure (mensagem de erro do servidor exibida na UI) | `ModalCaminho` prop `erro` | accept | A mensagem exibida é o `detail` que o próprio servidor local já devolvia e que a `Sidebar` já mostrava antes deste plano — o nível de exposição não muda, e o servidor só escuta em 127.0.0.1 |
| T-04-06-SC | Tampering | npm/pip install | mitigate | Nenhum pacote é instalado; `package.json`/`package-lock.json` fora do diff. Em particular, não adotar biblioteca de estado global para resolver o lift — o padrão de prop do `useJob` já existe no projeto |

Invariantes do `CLAUDE.md`: nenhuma operação física é criada; a varredura disparada
é somente leitura, como já era; nada sai da máquina.
