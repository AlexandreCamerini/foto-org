# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase closes 8 already-medido inconsistencies (`docs/AVALIACAO_UX.md` A.3/A.4/A.6/A.7, B.3/B.6/B.7/B.8),
all confirmed still open in `04-CONTEXT.md`. Seven of the eight (CONS-01/02/03/05/06/07/08) are reconciliation
against a design system that already exists — this contract states the exact target class/copy per call site,
not new visual language. The one genuinely open surface is CONS-04 (broken-image state), delegated to this
researcher by `04-CONTEXT.md` D-06 and resolved below.

## Dependencies / Blocks Planning

Two of the eight CONS items cannot be closed as pure frontend edits. Flag both to the planner before
estimating — do not scope them as CSS-only tasks:

1. **CONS-01 needs one backend field.** `SugestaoRow` (`webapp/src/api.ts:273-281`) and the
   `GET /api/sugestoes`/`GET /api/.../grupos` response it types have no `source_id` on the per-photo row today
   (`fotoorganizer/server/app.py`, sugestões endpoint). The selo cannot render without it. **Minimal fix:**
   add `source_id: int` to the row-level serialization only (not a formatted name string) — the frontend
   already has `rotuloDeFonte(fontes, sourceId)` (`webapp/src/fontes.ts:60`, already used by `App.tsx`/
   `Sidebar.tsx`) which resolves and disambiguates the display name client-side from the already-cached
   `["fontes"]` query. No new backend formatting logic needed, no new frontend helper needed — just the raw id.

2. **CONS-05's "Adicionar pasta" trigger must be lifted above `Sidebar.tsx`.** The modal
   (`ModalCaminho`, `modal === "pasta"` state) lives entirely inside `Sidebar.tsx` today, private to that
   component. Two of the three empty states that need to open it can't reach it as-is:
   - `Panorama.tsx`'s empty state — `Sidebar` isn't even mounted on the Panorama tab (`App.tsx`
     `ABAS_COM_FONTE = ["Biblioteca", "Revisão", "Viagens"]` excludes Panorama).
   - `PhotoGrid.tsx`/`Trips.tsx`'s empty states — `Sidebar` **is** mounted alongside them, but its modal state
     is a private `useState`, not exposed via props; a sibling component has no way to trigger it.

   **Contract, not implementation:** all four call sites (`Sidebar`'s own button, plus the three new empty-state
   buttons) must resolve to the exact same modal — same title "Caminho da pasta de fotos", same placeholder
   `/Users/voce/Pictures/Viagens`, same confirm action `job.escanear(caminho)`. The mechanism (lift state to
   `App.tsx`, pass a callback down to all four, or extract `ModalCaminho` + its trigger into a shared
   hook/context) is the planner's/executor's call — this spec only locks the visible contract: one button
   label ("Adicionar pasta…"), one modal, one confirm action, reachable from all four screens.

## Typography

Inherited base scale from `webapp/src/index.css` (`--text-micro` 11px, body 13px via `<html>`, `--text-realce`
15px) — unchanged. **What this phase changes is the Emphasis row**, which CONS-08 tokenizes and reconciles
project-wide (Phase 3 only fixed it in the files it touched; this phase finishes it everywhere).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (default) | 13px (`--text-corpo`) | 400 (no class) | browser default — unchanged, no new rule this phase |
| Label / secondary | 11px (`--text-micro`) | 400 | not tokenized |
| Panel title (`.titulo-painel`) | 11px, uppercase, `letter-spacing: 0.08em` | 400 | not tokenized |
| **Emphasis (title/filename/destination/selo-adjacent content)** | inherits context size | **500, via new token `--font-weight-titulo: 500` → utility `font-titulo`** | — |
| Display | not applicable | — | — |

**CONS-08 token contract (resolves the "Claude's Discretion" item in `04-CONTEXT.md` on exact class name):**

Add to `webapp/src/index.css` `@theme` block, in the `--font-weight-*` namespace so Tailwind 4 auto-generates
the utility:

```css
/* Peso único de ênfase — reconciliação full-codebase de font-semibold/font-medium
   convivendo sem regra (B.8). Mesmo valor (500) que font-medium já era; o ganho é
   nomear a decisão, não mudar o número. */
--font-weight-titulo: 500;
```

This generates the `font-titulo` utility class (Tailwind's `--font-weight-{name}` → `font-{name}` convention —
same mechanism that already produces the built-in `font-medium`/`font-semibold`). Using a **new named class**
rather than redefining `--font-weight-medium` is deliberate: it makes every migrated call site greppable and
makes a future stray `font-semibold`/`font-medium` (typed ad hoc instead of `font-titulo`) visibly a deviation,
not indistinguishable from the canonical token.

**Exhaustive migration list — every `font-semibold`/`font-medium` instance found in `webapp/src/` this session
(grep, non-test files), and the single locked exception:**

**New this phase — explicit exclusion from the accent list:** the CONS-01 (selo de fonte) and CONS-02 (selo

The wrong precedent to copy is `Duplicates.tsx:138` ("resolvido automaticamente" badge, `border-acento/40

**CONS-03/07 — button-importance hierarchy, resolved:**

`variante="solido"` (filled, the one visually loud button style) is reserved for exactly two categories,
confirmed by `04-CONTEXT.md` D-04:
1. The physical copy operation itself: `Operations.tsx:194` ("Copiar N arquivos" / "Executar plano" — already
   correct, no change).
2. Destructive modal confirmations (none exist in this phase's named scope — do not go looking for more).

Everything else that currently uses `solido` or a persistent-accent `contorno` override and is **named** in
CONS-03 migrates to the plain default `Botao` (`variante="contorno"`, no `className` color override):
- `Review.tsx:151` "Gerar/atualizar sugestões" — drop `variante="solido"`, use default.
- `RetomarScan.tsx:57` "Retomar" — drop the `className="border-acento text-acento hover:bg-cartao"` override,
  use default `Botao` (no `className` color override at all — the default contorno already reads as a real
  button without a colored border).

**Explicitly out of scope — do not touch as a drive-by:** Sidebar.tsx's `ModalReapontar`/`ModalAvisoApple`/
`ModalCaminho` confirm buttons (`variante="solido"` on "Reapontar"/"Continuar"/"Confirmar"). CONS-03's locked
scope in both `REQUIREMENTS.md` and `04-CONTEXT.md` names only "Retomar" and "Gerar sugestões" — expanding to
modal confirms is a separate call the product owner hasn't made.

**CONS-07 — "cancelar" hover, resolved:** per D-05, the criterion is "job in progress (real progress lost) =
red on hover only; edit/modal (nothing done yet) = neutral." Applying it:
- **Stays/already-correct:** `StatusBar.tsx` `hover:text-erro` (job cancel), `Sidebar.tsx`/`Review.tsx`
  `hover:bg-cartao` (modal/edit cancel) — no change needed, these already match the rule.
- **Fixes:** `Operations.tsx:213-215` — currently `<Botao tom="erro">Cancelar</Botao>`, which via `Botao`'s
  `TONS.erro` (`border-erro/40 bg-erro/10 text-erro hover:bg-erro/20`) is colored **at rest**, not just on
  hover — the one real violation. This cancels an in-progress copy job (real progress lost), so it keeps red,
  but only on hover, matching `StatusBar.tsx`'s exact pattern:
  ```tsx
  <Botao variante="fantasma" onClick={() => job.cancelar()} className="hover:text-erro">
    Cancelar
  </Botao>
  ```
  (drop `tom="erro"` entirely).

## Interaction Contract (Phase 4 specific)

Not part of the standard template, added because 3 of the 8 CONS items are new interactive states, not just
class-string reconciliation.

### CONS-04 — broken-image state (the delegated design surface, D-06)

**Scope boundary:** this applies to the **main high-resolution preview image only** — Loupe's large centered
`<img src={api.previewUrl(...)}>` and Duplicates' per-member `<figure><img src={api.previewUrl(...)}>`. It does
**not** apply to Loupe's filmstrip thumbnails (`api.thumbUrl`, already thumbnail-scale, out of this
requirement's "imagem em alta resolução" wording) — leave those untouched.

**Shared vocabulary, different layouts (per D-06: never the raw browser broken-image icon, Loupe and
Duplicates may differ from each other):** both reuse the `⊘` glyph already established by `Miniatura.tsx`/
`Trips.tsx` as this app's "no image" sign — this is what makes the new state read as "this app's error," not
generic. What differs is scale and copy verbosity, matched to each context's available space.

**Loupe (`Loupe.tsx`) — full-screen, one photo, room to explain:**
```tsx
const [falhouPreview, setFalhouPreview] = useState(false);
// reset alongside the existing setZoom100(false) in the index-change effect

{falhouPreview ? (
  <div className="flex flex-1 flex-col items-center justify-center gap-3 text-center">
    <span aria-hidden className="text-5xl text-texto-3">⊘</span>
    <div className="text-texto-2">Não foi possível carregar esta imagem em alta resolução.</div>
    <div className="text-texto-3">O arquivo pode ter sido movido, renomeado ou corrompido desde a catalogação.</div>
  </div>
) : (
  <img
    src={api.previewUrl(media.id)}
    alt={media.nome}
    draggable={false}
    onError={() => setFalhouPreview(true)}
    className={/* unchanged */}
  />
)}
```
The outer wrapper's `onClick={() => setZoom100((v) => !v)}` (zoom toggle) has nothing to toggle when the image
failed — guard it: `onClick={() => !falhouPreview && setZoom100((v) => !v)}`. Header (filename/date/index) and
footer (filmstrip) render unchanged — only the main image area swaps.

**Duplicates (`Duplicates.tsx`) — compact card inside a 2-3 column comparison grid:**
```tsx
const [falhouPreview, setFalhouPreview] = useState(false); // per-member, needs a small
  // subcomponent or a keyed state map — the current inline .map() body can't hold local
  // state per item as-is; extracting a `MembroFigura` component is the natural fix,
  // left to the executor

{falhouPreview ? (
  <div className="flex aspect-[4/3] w-full flex-col items-center justify-center gap-1 bg-cartao text-texto-3">
    <span aria-hidden className="text-2xl">⊘</span>
    <span className="text-texto-2">imagem indisponível</span>
  </div>
) : (
  <img
    src={api.previewUrl(m.media_id)}
    alt={m.nome}
    loading="lazy"
    onError={() => setFalhouPreview(true)}
    className="aspect-[4/3] w-full bg-black object-contain"
  />
)}
```
Note the background flips from `bg-black` (letterboxing for a successfully loaded `object-contain` image) to
`bg-cartao` (this app's established "empty/broken surface" color, same as `Miniatura`/`Trips`) in the error
state — do not keep `bg-black` for the error card, it would read as "still loading," not "failed." The
`<figure>` wrapper's role-based border (`border-ok` for principal, `border-borda opacity-50` for ignorado,
`border-borda` otherwise) is unaffected — it still reflects the member's role regardless of image load state.
The filename is already shown in `<figcaption>` below the image — do not repeat it inside the error state.

### CONS-01 — selo de fonte (per-sugestão, `Review.tsx`)

Fires when an item's `nome`+`data_capturada`+`camera` collide with an **adjacent** item in the rendered list
(different `media_id`) — D-01/D-02. Appears on **every** colliding item individually, not once at the group
header. Requires the `source_id` backend addition noted in Dependencies above.

**Implementation note (mirrors the CONS-02 note below):** `colide` is not a new field on `Item` — it's
computed by the caller (`FotosDoGrupo`'s `renderizar` callback, or its parent) by comparing each item to its
immediate neighbor(s) in the paginated list already fetched for the open group. Adjacency semantics, not new
API surface.

```tsx
<div className="flex min-w-0 items-center gap-1.5">
  <span className="truncate font-titulo">{s.nome}</span>
  {colide && (
    <span
      title={`Mesmo nome, data e câmera de outra sugestão nesta lista — fontes diferentes`}
      className="inline-flex shrink-0 items-center rounded-full border border-borda bg-cartao px-1.5 py-0.5 text-[11px] text-texto-2"
    >
      {rotuloDeFonte(fontes, s.source_id)}
    </span>
  )}
</div>
```
`fontes` comes from the same `["fontes"]` react-query cache App.tsx/Sidebar.tsx already populate — add the
query to `Review.tsx` (cheap, cache-shared, no duplicate request in practice).

### CONS-02 — selo álbum/evento (`Trips.tsx`, Eventos section only)

Fires when two cards **within the Eventos section** share the same `nome` (case-insensitive) — same
collision-only trigger pattern as CONS-01, not shown unconditionally on every card. Uses the deterministic
`metodo` field already typed (`Agrupamento.metodo`, `webapp/src/api.ts:198`) and already served by the API — no
backend change needed here (unlike CONS-01). Per D-03: `metodo === "album_externo"` → "Álbum"; any other value
→ "Evento detectado".

**Implementation note:** `Trips.tsx`'s `Card` component today has no section discriminator — `Secao`
renders the same `Card` for both Viagens and Eventos, so `Card` needs a new prop (e.g. `secao: "viagens" |
"eventos"`) plus a `colideNome` boolean computed by its parent `Secao` (name collisions within that section's
`itens` array) before this badge can render. Left to the executor, same as the Duplicates per-member state
extraction above — not a new visual decision, just plumbing this spec assumes exists.

Placed **top-left** of the card (the "Mapa" badge already owns top-right):
```tsx
{secao === "eventos" && colideNome && (
  <span className="absolute left-2 top-2 z-10 rounded-full border border-borda bg-janela/80 px-2 py-0.5 text-[11px] text-texto-2 backdrop-blur-sm">
    {grupo.metodo === "album_externo" ? "Álbum" : "Evento detectado"}
  </span>
)}
```
Same visual family as the existing "Mapa" badge (`border-borda`, `bg-janela/80`, `backdrop-blur-sm`,
`text-texto-2`) — deliberately not the accent-colored badge style `Duplicates.tsx` uses for "resolvido
automaticamente"; see Color section.

### CONS-06 — responsive stacking at `lg` (1024px)

D-08/D-09: below Tailwind's default `lg` breakpoint (1024px, not a custom value — none exists in this
codebase to follow), the Biblioteca toolbar (`App.tsx`, inside the `aba === "Biblioteca"` block, the bar
currently at lines ~296-400) stacks into exactly **two rows**. The Inspector (`w-72`, `App.tsx:434-436`) is
never collapsed or hidden — it is out of this breakpoint's scope entirely, unchanged at every width.

Group the toolbar's existing controls into two rows by intent, not by wrapping wherever they happen to
overflow:
- **Row 1 (scope/identity controls):** recorte chip, Lista/Mapa toggle, Tudo/Organizáveis/Fora-de-alcance
  toggle.
- **Row 2 (view/sort controls):** busca input, ordenação select, zoom slider.

```tsx
<div className="flex flex-col gap-2 border-b border-borda px-3 py-2 lg:flex-row lg:items-center lg:gap-2">
  <div className="flex flex-wrap items-center gap-2">
    {/* recorte chip, Lista/Mapa, Tudo/Organizáveis/Fora-de-alcance */}
  </div>
  <div className="flex flex-1 flex-wrap items-center gap-2">
    {/* busca, ordenação, flex-1 spacer, zoom */}
  </div>
</div>
```
At `lg` and above this collapses back to the single-row layout that exists today (`lg:flex-row` puts both
groups side by side). Below `lg`, `flex-col` stacks the two groups — never more than two rows regardless of
how narrow the window gets, satisfying "empilha em duas linhas," not N linhas.
