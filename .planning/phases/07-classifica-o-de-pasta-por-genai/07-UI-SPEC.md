## Layout & Component Inventory

### Entry point — no new tab, modal wizard from within Revisão

Per `ROADMAP.md` § Phase 7 UI hint: **"escopo estreito: um ponto de confirmação de custo antes
da sessão (modal/confirmação), não uma tela nova."** Do not add an entry to `ABAS` in `App.tsx`.
New button in `Review.tsx`'s existing header bar (`webapp/src/components/Review.tsx:156-163`),
placed to the left of `"Gerar/atualizar sugestões"`:

```tsx
<Botao variante="contorno" tamanho="md" onClick={() => setClassificacaoAberta(true)}>
  Classificar pastas por IA…
</Botao>
```

New component: `webapp/src/components/ClassificacaoPasta.tsx`. Rendered as a modal overlay using
`ModalCaminho.tsx`'s exact shell (`fixed inset-0 z-50 flex items-center justify-center bg-black/95`),
with a wider panel than the caminho modal (that one is a single text field; this one is a
multi-row wizard):

```
panel: "w-[720px] max-w-[92vw] max-h-[85vh] overflow-y-auto rounded-md border border-borda bg-painel p-4"
```

`Esc` closes the modal at any step **except** step 3 (Rodando) — the API call is already in
flight and synchronous; closing the dialog does not cancel it server-side (same non-cancellable
contract as `ClaudeAdvisor`'s call inside `gerar()` today). Disable the close affordance (`Esc`,
backdrop click, and any close button) during step 3 with a one-line note: `"A chamada já foi
enviada e não pode ser cancelada — aguarde a resposta."`.

### Wizard state machine — five steps, one component, no route change

```
0. Desligado (opt-in gate, shown only while flag is off)
      ↓ [Habilitar e continuar]
1. Candidatos (D-01: pre-filtered list, checkbox per row)
      ↓ [Avançar]                    ↑ [Voltar]
2. Custo (D-04/D-05: cost estimate, single confirm, no cap)
      ↓ [Confirmar e classificar]    ↑ [Voltar]
3. Rodando (single synchronous call in flight, non-cancellable)
      ↓ (auto-advance on response)
4. Revisão (D-03: antes/depois per folder, checkbox per row)
      ↓ [Aprovar N selecionadas]
5. Concluído (summary, closes modal)
```

Steps 1→2→3→4 happen within a single modal session (no page navigation). Re-opening the modal
after step 5 always restarts at step 1 (fresh candidate query) or step 0 if the flag was turned
back off via the revocation control (see Opt-in below).

#### Step 0 — Desligado (opt-in gate)

Shown when `GET /api/config` (or equivalent) reports `classificacao_pasta_genai: false`. This is
the **only** UI surface for this flag — there is no dedicated Configurações/Privacidade tab in
this codebase today (confirmed: `App.tsx`'s `ABAS` has none, and the sibling flag
`servicos_externos` has zero UI surface, TOML-only). Follow `TemplateEditor.tsx`'s precedent
(a settings control embedded in the screen that needs it, not a new global settings page) rather
than inventing a Configurações tab — same discretion class as Phase 6's shadcn-skip: a documented
call, not a placeholder.

```
┌──────────────────────────────────────────────────────────┐
│ ⚠  Classificação de pasta por IA está desligada            │
│                                                             │
│ Ao habilitar, o nome de cada pasta candidata e os metadados│
│ já catalogados (nunca imagens) são enviados ao Claude       │
│ Sonnet 5 numa única chamada por sessão, com custo estimado  │
│ mostrado antes de cada envio. Nada sai da máquina sem sua   │
│ confirmação explícita a cada sessão.                        │
│                                                             │
│ [ ] Habilitar classificação de pasta por IA                │
│                                                             │
│                              [Cancelar]  [Habilitar e continuar]│
└──────────────────────────────────────────────────────────┘
```

- Footer buttons: `"Cancelar"` is `Botao variante="fantasma"`, `"Habilitar e continuar"` is
  `Botao variante="solido"` (the only accent-colored control on this step) — same primary/secondary
  pairing as steps 2 and 4, so the step-advancing action is always the visual anchor.
- Checkbox required checked before `"Habilitar e continuar"` enables (`disabled` otherwise) —
  mirrors the explicit-consent pattern invariant 4 requires ("indicação visual prévia de quais
  dados serão enviados, finalidade... antes de habilitar").
  - `servicos_externos` (the master switch) must **also** be true for this feature to run at all
    (`07-RESEARCH.md` Pitfall 4: gate on both, never let this flag alone imply consent to any
    external call). If `servicos_externos` is false, step 0 shows a **different**, non-actionable
    message instead of the checkbox: `"Serviços externos estão desligados nas configurações do
    app — habilite [privacidade] servicos_externos antes de usar este recurso."` No checkbox is
    rendered in that case; this screen does not also toggle the master switch (out of scope — the
    master switch has never had UI surface and this phase doesn't add one for it).
- `"Habilitar e continuar"` calls `PUT /api/config/privacidade` (or the phase's own endpoint),
  then advances to step 1 in the same modal session — no reload, no re-click needed.
- **Revocation control** (invariant 4 requires "forma de revogação" to be visible, not just
  present in a TOML file): once enabled, every subsequent open of this modal shows a small
  `"Desligar"` text link in the step-1 header (`text-texto-3 hover:text-texto-2`, far right,
  not a button — low visual weight, always available, never buried). Clicking it returns to step
  0 immediately, unchecked.

#### Step 1 — Candidatos (D-01)

```
┌──────────────────────────────────────────────────────────┐
│ Pastas candidatas                              Desligar   │
│ Sistema pré-filtrou pastas com categoria OU cidade/país    │
│ vazios. Desmarque o que não quer incluir nesta sessão.     │
├──────────────────────────────────────────────────────────┤
│ [✓] …/Viagens/2024 - Portugal          categoria · 42 fotos│
│ [✓] …/Sem categoria/IMG_2024           cidade/país · 8 fotos│
│ [ ] …/Família/Aniversário Marina       categoria · 15 fotos│
│ …                                                          │
├──────────────────────────────────────────────────────────┤
│ 12 de 14 pastas selecionadas          [Cancelar] [Avançar] │
└──────────────────────────────────────────────────────────┘
```

- Footer buttons: `"Cancelar"` is `Botao variante="fantasma"`, `"Avançar"` is
  `Botao variante="solido"` — same pairing as step 0.

- Row shell: `flex items-center gap-3 px-3 py-1.5 border-b border-borda` (same rhythm as
  `Review.tsx`/`Operations.tsx` rows).
- Checkbox: native, Tailwind-styled, checked fill `--color-acento`, same as Phase 6's convention
  — **default checked** for every row (D-01's own phrasing is opt-out: "podendo desmarcar item
  pontual", not opt-in).
- Folder path: `font-titulo` (13px/500), truncated with the existing `pastaCurta`-style tail
  logic (`Review.tsx`'s `pastaCurta` helper — reuse verbatim, don't reinvent path truncation).
- Trailing tag: `text-[11px] text-texto-2`, states which field(s) are missing — `"categoria"`,
  `"cidade/país"`, or `"categoria · cidade/país"` when both are empty (D-01: "AO MENOS UM campo
  vazio" — the tag must show which one(s), not just "incompleto", so the dono can judge each row
  without opening it).
- Footer: live count `"{checked} de {total} pastas selecionadas"`, `"Avançar"` disabled when 0
  rows checked (`title="Selecione ao menos uma pasta"` on the disabled button, same
  disabled-with-reason convention as `EscritaExif.tsx`).
- Empty state (no candidates at all): replace the row list with the same empty-state pattern as
  `Review.tsx`'s `"Nada aqui"` — `"Nenhuma pasta com categoria ou cidade/país vazios no catálogo
  atual."` — and hide the footer buttons except `"Fechar"`.

#### Step 2 — Custo (D-04/D-05)

```
┌──────────────────────────────────────────────────────────┐
│ Custo estimado desta sessão                                │
│                                                             │
│ 12 pastas · 1 chamada ao Claude Sonnet 5                   │
│                                                             │
│ Entrada (estimada):     até 3.420 tokens · até R$ 0,034     │
│ Saída (estimativa):     até 6.000 tokens · até R$ 0,300     │
│ ─────────────────────────────────────────────────         │
│ Total estimado:         até R$ 0,334 (US$ 0,067)            │
│                                                             │
│ Nada foi enviado ainda — os dois números acima são          │
│ estimativas locais. Depois de confirmar, a contagem exata   │
│ da entrada aparece no resumo final. O valor acima é o teto, │
│ o custo real tende a ser menor.                             │
│                                                             │
│                              [Voltar]  [Confirmar e classificar]│
└──────────────────────────────────────────────────────────┘
```

- **Honesty framing is load-bearing, not decorative** (`07-RESEARCH.md` Pitfall 3, resolved by
  D-079 in `docs/DECISOES.md`): the dono chose the hybrid option over exact `count_tokens` before
  confirm, because that call transmits the payload — a call this early would violate ROADMAP
  Phase 7 success criterion 2 ("nada é enviado antes de ele confirmar"). Both numbers on this step
  are therefore local estimates, not one exact and one approximate: input and output cost both
  render in `--color-texto-3`, both carry `"até"` (up to) prefixed and `"(estimada)"` /
  `"(estimativa)"` suffixed on their own label — neither line gets the confident/exact treatment.
  The total line also carries `"até"` — there is no single unqualified number anywhere on this
  screen. This directly extends the same "nunca invente confiança sem base" discipline D-06
  already applies to evidence, now applied to a cost number. The exact number the input estimate
  was standing in for shows up later, honestly, in step 5's post-confirmation summary (see Step 5
  below) — the precision moves after the confirm gate instead of disappearing.
  - Do not use `--color-erro`/`--color-atencao` for the estimate — it's not a warning, it's an
    honest uncertainty band. Plain secondary-text token only.
  - Both currencies shown together (R$ primary, US$ parenthetical) — same "mesmo padrão do
    Advisor existente" D-04 asks for; `07-RESEARCH.md` confirms official Anthropic pricing is
    USD, so R$ is a converted display value — if the plan needs an FX-rate source/staleness
    caveat, that's a backend/data concern, not this contract's to resolve, but the UI must not
    imply the R$ figure carries the same precision as the USD one when a conversion is involved.
- No second confirmation, no checkbox, no typed confirmation phrase — **D-05 is explicit: no
  automatic cap, single button suffices.** Do not add a "type CONFIRM to proceed" pattern here;
  that would contradict the locked decision.
- `"Confirmar e classificar"` uses `Botao variante="solido"` (the only accent-colored control on
  this step) — the estimate itself must never be accent-colored, or the dono's eye lands on the
  (uncertain) number instead of the (certain) action.
- `"Voltar"` returns to step 1 with the same selection preserved (no re-query, no lost checkbox
  state).

#### Step 3 — Rodando

```
┌──────────────────────────────────────────────────────────┐
│                                                             │
│         Consultando Claude Sonnet 5…  (0:07)                │
│                                                             │
│    A chamada já foi enviada e não pode ser cancelada —      │
│    aguarde a resposta.                                      │
│                                                             │
└──────────────────────────────────────────────────────────┘
```

- No progress bar (a single request has no meaningful sub-progress to show — a fake bar would
  misrepresent certainty the same way a false-precision cost number would). An elapsed-time
  counter (`text-texto-2`, ticking seconds) is enough honest feedback that the app hasn't frozen.
- No close affordance active (see Entry point section above).
- On error (timeout/429/exception — never-crash contract): advance to a dedicated error state,
  not silently back to step 2. See Copywriting Contract, Error state row.

#### Step 4 — Revisão (D-03 antes/depois per folder)

```
┌──────────────────────────────────────────────────────────┐
│ Revisão — 10 propostas                                     │
├──────────────────────────────────────────────────────────┤
│ [✓] …/Viagens/2024 - Portugal                    ⓘ         │
│     antes: categoria — (vazio)                              │
│     depois: categoria — Viagens          [IA·pasta] [●●○ Média]│
├──────────────────────────────────────────────────────────┤
│ [✓] …/Sem categoria/IMG_2024                       ⓘ         │
│     antes: cidade/país — (vazio)                             │
│     depois: cidade/país — Lisboa, Portugal [IA·pasta] [●●● Alta]│
├──────────────────────────────────────────────────────────┤
│  ⚠ 2 pastas sem resposta confiável — Claude não teve         │
│    segurança pra classificar. Nenhuma sugestão foi criada.   │
│    Ver quais »                                               │
├──────────────────────────────────────────────────────────┤
│ 10 de 10 propostas selecionadas    [Fechar sem aprovar]      │
│                                     [Aprovar 10 selecionadas] │
└──────────────────────────────────────────────────────────┘
```

- Row shell: same as step 1 (`px-3 py-1.5 border-b border-borda`), but two-line content per row
  (antes/depois), not single-line.
- Checkbox: **default checked** (approve-by-default, same opt-out phrasing as D-01: "dono escolhe
  quais aceitar" reads as trim-from-the-batch, not build-up-from-empty — consistent with step 1's
  default). Unchecking = discard this folder's proposal entirely; it is never written as evidence.
- **Antes line:** `text-texto-2`, states the field name(s) that were empty and their prior value
  — always `"(vazio)"` for the field GenAI is filling (D-01's own filter guarantees this), never
  blank space with no label (same "explicit state, not blank field" discipline as D-06 below).
- **Depois line:** `font-titulo` for the proposed value(s), immediately followed by two pills:
  - **Origin pill** (`"IA · pasta"`): `rounded-full border border-herdado/40 bg-herdado/10
    text-herdado px-1.5 py-0.5 text-[11px]` — same pill shell as the existing `rotuloDeFonte`
    CONS-01 badge in `Review.tsx:312-319`, new label and new color-family (`herdado`, see Color
    section) so it reads as "derived/secondary signal," never confused with the plain
    `border-borda bg-cartao text-texto-2` neutral source-collision pill. **This is the
    distinguishability CONTEXT.md's CONS-01 reference asks for** — same visual technique (small
    pill next to the value), different label and color so a GenAI-origin proposal is never
    mistaken for the cluster Advisor's `"llm"` origin or a deterministic parse.
  - **Confidence badge**: the existing `Confianca` component, unmodified, fed the level the
    backend assigns from `SCORES_REFERENCIA["llm_pasta"]` (numeric value out of this contract's
    scope — see `07-RESEARCH.md` Open Question 1). No new visual logic; alta/média/baixa render
    exactly as everywhere else in the app.
- **`ⓘ` button** (top-right of each row, `Botao variante="fantasma" tamanho="sm"`): expands the
  `justificativa` text inline below the row, same interaction as `Review.tsx`'s `PorQue` popover
  (`porque === s.media_id` toggle pattern) — reuse the pattern, this is a new instance of the
  same "por quê?" affordance the rest of the app already has, not a new interaction idiom.
  Carries the same accessible-name pattern as `Review.tsx:337-338`'s equivalent button:
  `title="Por que esta proposta para {pasta}?"` and `aria-expanded={expandido}` — not just the
  click behavior, the accessible name too.
- **D-06 "sem resposta confiável" summary line** (not a row): a single collapsed line, never
  individual blank rows for ambiguous folders. `⚠` icon in `--color-atencao`, text
  `"{N} pastas sem resposta confiável — Claude não teve segurança pra classificar. Nenhuma
  sugestão foi criada."` `"Ver quais »"` expands a plain list of folder names (`text-texto-3`,
  no checkbox, no depois line — there is nothing to approve). **This satisfies D-06's explicit
  requirement** ("nunca um campo em branco que pareça bug") — the folders exist in this list as
  a named, explained absence, never as a row with an empty depois field.
- Footer: `"Aprovar {N} selecionadas"` (`Botao variante="solido"`) and `"Fechar sem aprovar"`
  (`Botao variante="fantasma"`) — closing without approving discards every proposal in this
  session (nothing partially applied outside the checkbox state), consistent with never silently
  keeping unconfirmed data.

#### Step 5 — Concluído

```
┌──────────────────────────────────────────────────────────┐
│ ✓ 10 pastas classificadas                                  │
│                                                             │
│ Custo real desta sessão: R$ 0,031 (3.180 tokens de entrada, │
│ contagem exata)                                             │
│                                                             │
│ As sugestões aparecem em Revisão na próxima geração de       │
│ sugestões.                                                  │
│                                                             │
│                                                    [Fechar] │
└──────────────────────────────────────────────────────────┘
```

- `✓` in `--color-ok`. Copy explicitly sets expectation that this doesn't retroactively touch
  the currently-open Revisão list — it feeds the *next* `SuggestionEngine.gerar()` run
  (`"Gerar/atualizar sugestões"` in `Review.tsx`), per the cascade design in `07-RESEARCH.md`.
  Do not imply an instant appearance in the grid behind the modal.
- **Real-cost line (D-079, hybrid decision):** `text-texto-2`, sits between the heading and the
  cascade-timing body copy. This is the payoff of the hybrid choice — the exact number step 2
  could only estimate now renders with the confidence step 2 explicitly withheld. No `"até"`
  prefix here (`contar_exato()` already ran, immediately before `messages.create`, so this is the
  real transmitted count, not a ceiling). If `contar_exato()` failed (never-crash contract, 07-03)
  and fell back to `0`, render the line with the estimated figure from step 2 instead and the
  suffix `"(estimativa — contagem exata indisponível)"` rather than silently showing `R$ 0,00`,
  which would misstate the real cost as free.

### Extension to `PorQue` (Review.tsx) — origin pill for GenAI evidence in the general flow

Once an approved GenAI proposal round-trips through the cascade and appears as a normal
`Evidencia` in `Review.tsx`'s existing `PorQue` component (`Review.tsx:463-493`), it must remain
distinguishable there too — not only inside this phase's own modal. Today `PorQue` renders
`ev.campo`, `ev.valor`, `ev.justificativa` but never `ev.origem` (confirmed: `Review.tsx:481-489`
has no origin rendering at all). Add the same origin pill used in step 4 above, conditionally,
next to the `Confianca` dot-cluster on any evidence row whose `ev.origem === "llm_pasta"`:

```tsx
<Confianca nivel={ev.nivel} rotulo={false} />
{ev.origem === "llm_pasta" && (
  <span className="rounded-full border border-herdado/40 bg-herdado/10 px-1.5 py-0.5 text-[11px] text-herdado">
    IA · pasta
  </span>
)}
```

This is the change that actually closes CONTEXT.md's CONS-01 reference end-to-end: the pill isn't
only visible inside this phase's own wizard, it survives into the shared Revisão surface where
the dono compares a GenAI-derived suggestion against a deterministic one.

## Open Items for Planner (not blocking this contract, but must be routed)

These are explicitly **not** resolved by this UI-SPEC and must not be silently locked during
planning — both are called out in `07-RESEARCH.md` as needing a routed decision, not a UI
decision:

1. **`SCORES_REFERENCIA["llm_pasta"]` numeric value** — this contract only specifies that the
   existing `Confianca` component renders whatever level the backend assigns; it does not (and
   should not) fix the number. Route through discuss-phase or `checkpoint:human-verify` per
   `07-RESEARCH.md` Pitfall 2.
2. **Persistence table shape (`PastaClassificada` or equivalent)** — this contract assumes
   step 4's "approve" action durably persists the folder→evidence mapping in a way that survives
   `SuggestionEngine.gerar()` regeneration (`07-RESEARCH.md` Pattern 3/Pitfall 1), but the exact
   schema is a backend decision outside this contract's scope.
3. **Exact config endpoint for the opt-in flag** (`GET`/`PUT` shape) — this contract assumes a
   config read/write round-trip exists or will exist for `classificacao_pasta_genai`
   (`07-RESEARCH.md`'s `PrivacySettings` proposal); the exact route name is a backend/planner
   decision, not fixed here.
