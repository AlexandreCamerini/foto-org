# Phase 6 — UI Design Contract: Escrita EXIF de localização

> Visual and interaction contract for the new `EscritaExif.tsx` component and its `Localização`
> tab. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-rolled Tailwind design system, not shadcn |
| Preset | not applicable |
| Component library | none (project-owned primitives: `ui/Botao.tsx`, `components/Confianca.tsx`, `components/Miniatura.tsx` — reuse, do not fork) |

(`docs/DIRECAO_DE_ARTE.md`, tokens in `webapp/src/index.css`), and `CLAUDE.md` explicitly
instructs "UI segue `docs/DIRECAO_DE_ARTE.md`... Não inventar estilo ad-hoc." Introducing shadcn
now would fork the design language mid-project. `Tool: none` is final for this phase, not a
placeholder pending user confirmation.

them without a concrete need.

## Color

Reuses the existing semantic palette (`webapp/src/index.css`). No new CSS custom property is
introduced this phase — see the discretion note on `--color-herdado` reuse below.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-janela` `#08090a` | Window/page background |
| Secondary (30%) | `--color-painel` `rgba(255,255,255,.02)` / `--color-cartao` `rgba(255,255,255,.05)` | Plan list sidebar, row backgrounds, header bar, detail panel chrome |
| Accent (10%) | `--color-acento` `#e8eaee` | Reserved for: primary CTA button fill ("Gravar N arquivos", `Botao variante="solido"`), checked-checkbox fill, selected-plan row highlight in the sidebar, focus ring |
| Destructive | not applicable — this phase has no destructive action (never overwrites, never deletes, invariant 1-3) | N/A |

Accent reserved for: the "Gravar N arquivos" button, the checkbox's checked-state fill, the
selected-plan sidebar row, and keyboard focus rings. Never used to color a badge, a status word,
or a field chip — those use the semantic tokens below, per `docs/DIRECAO_DE_ARTE.md`'s "confiança
é quantidade, não semáforo" discipline (color only where it signals state, always paired with a
text label, never as decoration).

### Additional semantic tokens used (already declared, reused with explicit per-phase meaning)

| Token | Value | Meaning in this phase |
|-------|-------|------------------------|
| `--color-atencao` | `#c2833a` (amber) | Unsupported-format badge (D-05) and sync-folder-warning badge (D-07) — both are "olhe aqui" cases, same color family as the codebase's existing low-confidence/attention convention. | `--color-ok` | `#6e9a78` | Post-execution: field successfully verified-written (diff-confirmed) |
| `--color-erro` | `#a8615a` | Post-execution: field write failed / diff detected an unexpected change |

## Layout & Component Inventory

### Entry point: new tab, global scope (discretion call)

Add `"Localização"` to the `ABAS` array in `App.tsx`, positioned after `"Operações"` (last —
mirrors its role as the other "physical write" screen). It is **not** added to
`ABAS_COM_FONTE`: per `Operations.tsx`'s precedent, this is a plan-object screen, not a
per-`fonte`-filtered media view. **Explicit discretion call, since CONTEXT.md/RESEARCH.md are
silent on scope:** the plan is **global** — one dry-run plan covering every catalogued file with
at least one empty location field and an inferred value available, not scoped per source. This
matches D-01's "aprova o plano dry-run inteiro de uma vez" and `Operations.tsx`'s one-plan-object
model. Do not build a per-`fonte` picker for this phase.

`DICAS["Localização"]`: `"revise o plano linha a linha; desmarque o que não quer gravar — o original só muda depois de aprovar"`.

### Screen shape: two-pane, mirrors `Operations.tsx` structurally

```
┌──────────────┬─────────────────────────────────────────────┐
│ Sidebar      │  Header: Rodar dry-run · Gravar N arquivos   │
│ (plan list,  │  Veredito line (dry-run summary)             │
│  w-72, same  ├───────────────────────────────────────────── │
│  as Ops)     │  Row list (scroll), one row per file          │
│              │  Auditoria <details> (post-execution)         │
└──────────────┴─────────────────────────────────────────────┘
```

New component: `webapp/src/components/EscritaExif.tsx`. Reuse verbatim from `Operations.tsx`:
the sidebar plan-list pattern, the header action-bar layout, the `veredito()`-style summary-line
function, the `<details>` audit collapsible. **Do not** reuse `Operations.tsx`'s `destino` text
input — this phase writes in place, there is no destination path to choose. The "Criar plano"
action needs no text field; it is a single button ("Criar plano de escrita") that triggers
candidate discovery server-side.

**Primary focal point:** the veredito summary line + the `"Gravar N arquivos"` button. These
are the only accent-colored (`#e8eaee`) elements on the screen besides row selection/focus —
everything else (badges, warnings, XMP offer) uses the semantic status tokens
(`atencao`/`ok`/`erro`/`herdado`), never accent. The dono's eye should land on "how many, and
the one button that acts," not on any individual row.

### Row anatomy — three row types, one list

Every row is `flex items-center gap-3 px-3 py-1.5 border-b border-borda` (same shell as
`Operations.tsx`/`Review.tsx` rows). Content differs by row type below. **A file can be both
Type B and Type C at once** (unsupported format AND inside a synced folder) — both badges render,
stacked with `flex gap-1.5`, never merged into one.

#### Checkbox semantics — NOT uniform across row types (must be explicit, executor will get this wrong otherwise)

Native `<input type="checkbox">`, Tailwind-styled (no new dependency, per RESEARCH.md Pitfall
6 — there is no existing checkbox component to extend). Checked fill uses `--color-acento`;
unchecked is an outlined box, `border-borda-forte`.

**Default state is NOT uniform either — explicit discretion call:**
- **Type A and Type C default to checked.** D-02's own phrasing is opt-out ("desmarcar itens
  pontuais... não é tudo-ou-nada") — the batch starts full, the dono trims it.
- **Type B (XMP sidecar) defaults to unchecked.** D-06's phrasing is opt-in ("o dono decide se
  quer esse caminho"), not opt-out — unlike the primary write batch, the sidecar is an
  alternative the dono actively chooses per file, not a default action he'd have to notice and
  cancel. Pre-checking it would silently create `.xmp` files next to originals the dono never
  asked to touch. If this reads wrong to the dono during verification, the fix is a one-line
  default flip, not a redesign — but ship unchecked-by-default as the starting contract.

| Row type | What the checkbox controls |
|----------|------------------------------|
| **A — normal write row** | Include this file's EXIF direct-write in the batch. Unchecking removes the whole file from this execution (all 3 fields), not per-field — D-08 already locks "3 fields together, no per-field selection." |
| **B — unsupported-format row** | **Different meaning:** there is no EXIF write path for this row (EXIF-05). The checkbox controls whether to include the **XMP sidecar write** as a substitute. Checked = "write `foto.<ext>.xmp` with the inferred fields"; unchecked = "skip this file entirely this run." Label the checkbox explicitly ("Gravar sidecar .xmp para este arquivo") — do not let it look identical to Type A's checkbox with no copy differentiation. |
| **C — sync-folder-warning row** | Same meaning as Type A (include/exclude from the batch) — D-07 is explicit that this is a visible warning, not a block. If a file is *also* Type B, the checkbox follows Type B's rule (XMP sidecar), and the sync warning badge still renders alongside. |

#### Type A — normal write row

```
[✓] filename.jpg                              [GPS chip] [Cidade chip] [País chip]
```
- Filename: `font-titulo` (13px/500), truncate.
- Field chips: one per location field, `rounded-full` pill (project's established pill
  convention for compact status), `text-[11px]` , `px-2 py-0.5`, `border border-borda`.
  - Will-write state: chip shows the value preview, e.g. `GPS -23.5505, -46.6333` /
    `Cidade São Paulo` / `País Brasil` — border `border-borda`, text `text-texto-2`.
  - Already-filled / skip state (EXIF-02 success criterion 2): chip text
    `Cidade já preenchida` — `text-texto-2`, no accent, **not** `text-erro` (this is expected
    behavior, not a problem; same token as the `pulado` status row below — one token for this
    state everywhere it appears). Tooltip/title shows the existing value:
    `title="já preenchido: Rio de Janeiro — não sobrescrito"`.

#### Type B — unsupported-format row (D-05/D-06)

```
[✓] filename.cr3   [⚠ Formato não suportado — CR3 não testado]  [⇢ sidecar .xmp]
    Gravar sidecar .xmp para este arquivo  [GPS chip*] [Cidade chip*] [País chip*]
```
- Row background: subtle tint to separate from Type A at a glance —
  `bg-atencao/5` (5% wash of the amber token over the row, not a saturated fill — consistent with
  the project's opacity-over-color-fill convention for surfaces).
- Badge 1 (format): pill, `border-atencao/40 bg-atencao/10 text-atencao`, icon `⚠`, label
  `"Formato não suportado"` + reason inline or in `title`: `"CR3 — sem teste de escrita neste acervo"` (EXIF-05: reason always visible, never just the badge alone).
- Badge 2 (path marker, D-06 visual-distinctness requirement): pill, `border-borda
  text-herdado`, icon `⇢`, label `"sidecar .xmp"` — this is the element that makes the row
  unmistakably NOT a direct-EXIF-write row. Always renders together with Badge 1; never appears
  alone (a row only gets the sidecar offer because it's unsupported).
- Field chips (marked `*` above): same 3-chip layout as Type A, but captioned "iriam para o
  sidecar" (or a small `→ .xmp` suffix on each chip) so the value preview doesn't read as "will
  be written to the original" — this is the second, redundant signal (beyond Badge 2) that
  RESEARCH.md's D-06 explicitly asks for: the dono must never confuse the two write paths.

#### Type C — sync-folder-warning row (D-07)

```
[✓] filename.jpg   [☁ Pasta sincronizada — iCloud Drive]        [GPS chip] [Cidade chip] [País chip]
```
- Badge: pill, `border-atencao/40 bg-atencao/10 text-atencao`, icon `☁`, label
  `"Pasta sincronizada"` + service name (`"iCloud Drive"` / `"Dropbox"` / `"Nuvem"` per
  `sync_detect.py`'s return value). `title` carries the full risk sentence: `"O app de sincronização pode sobrescrever este arquivo com a versão antiga ou gerar conflito silencioso. Você decide incluir ou não."`
- Field chips: identical to Type A (this row still writes EXIF directly unless also Type B) —
  the warning is additive, not a different write path.

### Post-execution status vocabulary (extends `Operations.tsx`'s `CORES_STATUS`, does not reuse it as-is)

`Operations.tsx`'s four-state map (`concluida/erro/cancelada/executando`) is insufficient — this
phase needs a fifth category that is neither success nor failure: a deliberate skip. Declare a
dedicated map, do not extend the imported one:

| Status | Color/class | Copy |
|--------|-------------|------|
| `pendente` | `text-texto-3` | (pre-dry-run, default) |
| `pronto` | `text-texto-2` | "pronto para gravar" |
| `pulado` | `text-texto-2` (neutral, not `text-erro` — same token as the Type A skip chip) | "pulado — campo já preenchido" |
| `formato_nao_suportado` | `text-atencao` | "formato não suportado" (Type B badge already carries this — row-level status text is redundant reinforcement in the post-dry-run summary line) |
| `gravado` | `text-ok` | "gravado e verificado" |
| `sidecar_gravado` | `text-herdado` | "sidecar .xmp gravado" |
| `falha` / `falha_parcial` | `text-erro` | "falha — ver tags abaixo" (never just "erro" with no detail, see per-tag breakdown below) |

### Post-execution per-tag failure breakdown (EXIF-03/D-04, success criterion 4 — no existing UI precedent, be exact)

`Operations.tsx`'s flat `acao · resultado` audit line is **not sufficient** for this requirement.
A row with `status="falha"` or `"falha_parcial"` renders an inline 3-segment breakdown directly
under the filename — same list position where Type A's field chips sit, replacing them for that
row once execution has run:

```
[✗] filename.dng                              ✓ GPS   ✓ Cidade   ✗ País
    falha — País: valor rejeitado pelo exiftool (ver auditoria)
```

- Each of the 3 fields renders as `glyph + label`, `text-[11px]`, `gap-1`:
  - Written and verified: `✓` in `text-ok`, label `text-texto-2`.
  - Failed (diff shows it did not land, or landed wrong): `✗` in `text-erro`, label `text-erro`.
  - Not attempted this run (already filled, skipped before the failure): `—` in `text-texto-3`,
    label `text-texto-3`.
- Below the 3-segment strip: one line of `text-[11px] text-erro`, the specific reason (from the
  audit `detalhe` JSON), not a generic "write failed."
- The existing `<details>` "Auditoria" collapsible (reused verbatim from `Operations.tsx`)
  remains the full historical log across all plans/executions — the inline breakdown above is
  the immediate, in-context signal; the `<details>` block is the audit trail. Both are required,
  neither replaces the other.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `"Gravar {N} arquivos"` — same construction as `Operations.tsx`'s `"Copiar {N} arquivos"`, `Botao variante="solido"`, disabled until dry-run has run and at least one row is checked |
| Secondary action | `"Rodar dry-run"` (verbatim reuse of `Operations.tsx`'s label — same verb for the same concept, don't invent a synonym) |
| Create-plan action | `"Criar plano de escrita"` (no destination field, unlike Operations' `"Criar plano"` — this button alone triggers candidate discovery) |
| Empty state heading | `"Nada para gravar"` |
| Empty state body | `"Todo arquivo catalogado já tem GPS, cidade e país preenchidos, ou nenhuma sugestão de localização foi gerada ainda. Gere sugestões em Revisão e aprove-as antes de criar um plano aqui."` |
| Error state (plan-level, dry-run/execution failure) | `"Não foi possível simular: {motivo técnico}. Verifique se o volume está montado e tente de novo."` |
| Error state (row-level, EXIF-03 partial failure) | `"falha — {campo}: {motivo}"`, e.g. `"falha — País: valor rejeitado pelo exiftool (ver auditoria)"` — always names the specific field, never a bare "erro" |
| Skip reason (row-level, EXIF-02) | `"já preenchido"` inline, full value in `title`: `"já preenchido: {valor existente} — não sobrescrito"` |
| Unsupported-format reason (EXIF-05) | `"{EXT} — {motivo}"`, e.g. `"CR3 — sem teste de escrita neste acervo"` / `"HEIC — reprovado no teste empírico (ver docs/DECISOES.md)"` |
| XMP sidecar offer | Checkbox label: `"Gravar sidecar .xmp para este arquivo"`; badge label: `"sidecar .xmp"` |
| Sync-folder warning | Badge label: `"Pasta sincronizada — {serviço}"`; tooltip: `"O app de sincronização pode sobrescrever este arquivo com a versão antiga ou gerar conflito silencioso. Você decide incluir ou não."` |
| Destructive confirmation | **Not applicable this phase** — no destructive action exists (invariants 1-3: never overwrites, never deletes, dry-run always precedes write). The closest analog, "Gravar N arquivos," is a physical write but not destructive (new-field-only, never overwrites) and needs no confirmation dialog beyond the dry-run review itself, consistent with `Operations.tsx`'s precedent (no confirm modal before "Copiar") |
